# DynamicDialog

A modern and flexible dialog component that provides an advanced user experience with compound component pattern support, drag & drop functionality, resizing capabilities, responsive design, and real fullViewport mode using the browser's Fullscreen API.

## Table of Contents

- [Basic Usage](#basic-usage)
- [Props API](#props-api)
- [Examples](#examples)
- [Rules and Best Practices](#rules-and-best-practices)

```tsx
import { DynamicDialog, DynamicDialogHeader, DynamicDialogBody, DynamicDialogFooter } from '@webdoxclm/design-system/components/dynamic-dialog/next'
```

## Basic Usage

Minimum example to start using the component.

<Story of={DynamicDialogStories.Default} />

```tsx
import { DynamicDialog, DynamicDialogHeader, DynamicDialogBody, DynamicDialogFooter } from '@webdoxclm/design-system/components/dynamic-dialog/next'

export default function App() {
  const [isOpen, setIsOpen] = useState(false)

  return (
    <DynamicDialog isOpen={isOpen} onClose={() => setIsOpen(false)}>
      <DynamicDialogHeader title="Basic Dialog" />
      <DynamicDialogBody>
        <p>Dialog content here...</p>
      </DynamicDialogBody>
      <DynamicDialogFooter>
        <Button>Close</Button>
      </DynamicDialogFooter>
    </DynamicDialog>
  )
}
```

## Rules and Best Practices

### Back Button and Icon Usage

**❌ Avoid using back button and icon together**
- It's recommended not to use the back button alongside an icon
- Prioritize using one or the other based on the usage context

```tsx
// ❌ Bad - Both back button and icon - Only in specific cases and validated by the design team
<DynamicDialogHeader
  title="Step 2: Details"
  icon={<FormIcon />}
  backButton={<BackButton onClick={goBack} />}
/>

// ✅ Good - Only back button
<DynamicDialogHeader
  title="Step 2: Details"
  backButton={<BackButton onClick={goBack} />}
/>

// ✅ Good - Only icon
<DynamicDialogHeader
  title="User Settings"
  icon={<SettingsIcon />}
/>
```

### Single Dynamic Dialog Rule

**❌ Never use multiple Dynamic dialogs on the same screen**
- If a view can execute two "Dynamic" components for different contexts (e.g., one for comments and another for Brain or Legal chat), only one can remain open
- Other visible dialogs on screen must be automatically closed or minimized

```tsx
// ❌ Bad - Multiple dialogs open simultaneously
const [commentsOpen, setCommentsOpen] = useState(false)
const [chatOpen, setChatOpen] = useState(false)

// ✅ Good - Only one dialog open at a time
const [activeDialog, setActiveDialog] = useState(null)

const openComments = () => {
  setActiveDialog('comments')
  setChatOpen(false) // Close other dialog
}

const openChat = () => {
  setActiveDialog('chat')
  setCommentsOpen(false) // Close other dialog
}
```

### Header Action Saturation

**❌ Avoid excessive actions that compromise the title or left-side elements**
- Keep header actions minimal and focused
- Don't overcrowd the header with too many buttons or controls

```tsx
// ❌ Bad - Too many actions crowding the header
<DynamicDialogHeader
  title="User Profile"
  actions={
    <div style={{ display: "flex", gap: "4px" }}>
      <Button size="24px">Edit</Button>
      <Button size="24px">Delete</Button>
      <Button size="24px">Export</Button>
      <Button size="24px">Share</Button>
      <Button size="24px">Archive</Button>
    </div>
  }
/>

// ✅ Good - Minimal, focused actions
<DynamicDialogHeader
  title="User Profile"
  actions={
    <div style={{ display: "flex", gap: "8px" }}>
      <Button size="32px">Edit</Button>
      <Button size="32px" kind="primary">Save</Button>
    </div>
  }
/>
```

### Action Height Limitations

**❌ Avoid using components with height greater than 32px**
- Keep action elements within the 32px height limit
- This ensures proper alignment and visual consistency

```tsx
// ❌ Bad - Actions taller than 32px
<DynamicDialogHeader
  title="Document Editor"
  actions={
    <Button size="40px">Large Button</Button> // Too tall
  }
/>

// ✅ Good - Actions within 32px height limit
<DynamicDialogHeader
  title="Document Editor"
  actions={
    <Button size="32px">Edit</Button> // Correct height
  }
/>
```

### Additional Actions Guidelines

**Use additional actions sparingly and purposefully**

#### IconButton Actions (1-2 recommended)
```tsx
// ✅ Good - 1-2 IconButton actions
<DynamicDialogHeader
  title="File Manager"
  actions={
    <div style={{ display: "flex", gap: "8px" }}>
      <IconButton icon={<RefreshIcon />} />
      <IconButton icon={<SettingsIcon />} />
    </div>
  }
/>
```

#### Other Element Actions (1 recommended)
```tsx
// ✅ Good - Single action for other elements
<DynamicDialogHeader
  title="User Settings"
  actions={
    <Button size="32px" kind="primary">Save</Button>
  }
/>
```

#### Multiple Actions Solution
**When you need more actions than can be displayed visually, use a dropdown:**

```tsx
// ✅ Good - Dropdown for multiple actions
<DynamicDialogHeader
  title="Advanced Settings"
  actions={
    <div style={{ display: "flex", gap: "8px" }}>
      <Button size="32px">Save</Button>
      <Dropdown
        trigger={<Button size="32px">More Actions</Button>}
        items={[
          { label: 'Export', onClick: handleExport },
          { label: 'Import', onClick: handleImport },
          { label: 'Reset', onClick: handleReset },
          { label: 'Archive', onClick: handleArchive }
        ]}
      />
    </div>
  }
/>
```

### Summary of Key Rules

1. **Back Button + Icon**: Use one or the other, not both
2. **Single Dialog**: Only one Dynamic dialog open per screen
3. **Header Actions**: Keep minimal and don't overcrowd
4. **Action Height**: Maximum 32px height for all actions
5. **Action Count**: 1-2 IconButtons or 1 other element
6. **Multiple Actions**: Use dropdown for overflow actions

Following these rules ensures a consistent, user-friendly experience across all Dynamic dialog implementations.

### Component Implementation

The component automatically applies these data-testids to the appropriate elements:

```tsx
<DynamicDialog
  dataTestId="user-settings"
  isOpen={isOpen}
  onClose={() => setIsOpen(false)}
>
  <DynamicDialogHeader
    dataTestId="profile-edit"
    title="Edit Profile"
  />
  <DynamicDialogBody
    dataTestId="form-content"
  >
    {/* Form content */}
  </DynamicDialogBody>
  <DynamicDialogFooter
    dataTestId="action-buttons"
  >
    <Button>Cancel</Button>
    <Button kind="primary">Save</Button>
  </DynamicDialogFooter>
</DynamicDialog>
// Result: 'dynamic-dialog-user-settings', 'dynamic-dialog-header-profile-edit', etc.
```



### Best Practices

1. **Use descriptive custom IDs**: Choose meaningful identifiers that describe the dialog's purpose
2. **Keep IDs consistent**: Use the same custom ID across all sub-components of a dialog
3. **Avoid special characters**: Use only letters, numbers, and hyphens in custom IDs
4. **Test ID uniqueness**: Ensure generated test IDs are unique within your test suite

```tsx
// ✅ Good - Descriptive and consistent
const dialogId = 'user-profile-edit';
<DynamicDialog dataTestId={dialogId}>
  <DynamicDialogHeader dataTestId={dialogId} />
  <DynamicDialogBody dataTestId={dialogId} />
  <DynamicDialogFooter dataTestId={dialogId} />
</DynamicDialog>

// ❌ Bad - Inconsistent and unclear
<DynamicDialog dataTestId="dialog1">
  <DynamicDialogHeader dataTestId="header" />
  <DynamicDialogBody dataTestId="body" />
  <DynamicDialogFooter dataTestId="footer" />
</DynamicDialog>
```
